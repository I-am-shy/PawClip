## 呼出回历史页 + 右键菜单/查看浮层

两个需求：
1. **每次呼出默认剪贴板历史页**。根因有二：show 事件里根本没切视图；且
   事件轮询是 `view === 'panel'` 才开的——用户停在其他视图收起面板后再呼出，
   前端**收不到 show**，"切回去"的命令永远到不了。修复：轮询常开（注释写明
   代价：其他视图上每 400ms 一次空 TakeEvents）；show → setTrashed(false) +
   nextView='panel' + showNonce++。focusSearchNonce 改名 showNonce，Panel 用它
   一次性重置：清搜索/类型/置顶/预览/浮层/多选 + refresh()（顺手重查，
   否则呼出后看不到收起期间新复制的内容）。
2. **右键菜单（复制/查看）+ 只读查看浮层（可缩放）**。
   - ContextMenu.tsx：页面内画菜单（内容依赖前端才知道的状态）。
     坑：window 的 mousedown 关闭监听**必须用冒泡阶段**——捕获阶段会先于
     React 的 onClick 处理，点菜单项时菜单先被卸掉，菜单项永远点不中；
     菜单项自身 onMouseDown stopPropagation 拦冒泡即可。
   - ContentViewer.tsx：文本（⌘+滚轮缩字号、pre 不软换行、user-select:text）
     / 图片（滚轮以**指针**为锚点缩放，offset' = p*(1-ratio)+offset*ratio；
     pointer capture 拖拽平移；双击复位；大图 onLoad 自动适应窗口、小图不放大；
     −/＋/百分比/适应窗口）/ 文件（路径列表，点击 RevealPath）。
     React 的 onWheel 是 passive 的，preventDefault 无效 → 必须原生
     addEventListener(..., {passive:false})。
     浮层开着时吞掉 Esc/空格/方向键等单键（捕获阶段），⌘C 放行；
     Panel 的 Esc 层级（清搜索→收起）不会被误触发。
   - 右键把光标落到该行（多选收成单选）：菜单动作作用对象与视觉一致。
   - 浮层缩放状态用 ref 镜像（连续滚轮时 state 是旧渲染值）。

实测（harness 加了 3 条假数据 + Get + __emit 事件入口）：
菜单定位/边界收拢、复制→CopyOnly 调用、文本浮层缩放 100%→156%→复位、
图片滚轮锚点偏移精确等于公式值、双击复位、适应窗口 (300-24)/640=0.43125、
Esc 只关浮层（搜索词保留、无 HidePanel）、呼出重置（预览关/搜索清/焦点回搜索框）、
从设置页呼出回历史页。全量 4 层绿。

## 修「打开文件管理器后出现透明窗口」

现象：在「查看」浮层里点文件路径 / 设置页点「打开数据目录」→ 访达（文件管理器）
弹出后，屏幕上出现一个透明的窗口。

根因分析（无法自行复现：osascript 键盘自动化被 TCC 拒 -10004，只能读码推断）：
- 面板窗口是**非不透明**的（panel_darwin.m `setOpaque:NO` + `clearColor`，
  为的是让系统投影跟着圆角卡片走），自己一个像素都不画，可见性完全依赖
  WKWebView 合成内容。**所以"透明窗口"只有一种成因：窗口可见 + 内容没合成。**
  前端这边可以排除：body/`.viewer` 都是不透明底色，全库无 backdrop-filter。
- 踩进去的时机：`open` 让访达激活 → 本 App 失去活跃 → 面板丢 key，而失焦
  自动收起要等 80ms 复核才发现（panel_darwin.m PawClip_ScheduleBlurCheck），
  于是 orderOut 落在 **App 已不活跃**的时刻；窗口再被呼出时
  `orderFrontRegardless` + `makeKeyWindow` 都**不激活 App**（免抢焦点设计要求），
  WebKit 未必马上重新合成 → 用户看到空壳。

修复：`revealAndStepBack`（dialogs.go）——交给系统文件管理器**之前**先
`HidePanel()`，让 orderOut 发生在面板仍持有键盘、App 仍活跃的时刻。只在
`ui.closeOnBlur` 为真时收，免得把「面板钉在屏幕上」那个设置弄失效。
顺带去掉原来「访达都起来了面板还赖 100ms」的观感。

留给用户的取证手段：窗口状态探针 `PAWCLIP_PANEL_DIAG=1`（默认关闭、零成本），
从终端起 App，每次显隐/失焦判定打一行
`visible/key/appActive/modal/webInPanel/frame`。`webInPanel=0` 说明 WebView
已不在面板视图树里（那是另一种成因，需要另修）。已记入 DESIGN.md §7 第 11 条。

测试：`TestReveal_StepsBackBeforeHandingOffToTheFileManager`（钉**时序**，不是
"最后收起了没有"）+ `TestReveal_KeepsPanelWhenCloseOnBlurIsOff`。做了变异测试
验证承重：把 hide 挪到 reveal 之后，测试按预期红（报错信息正是那句"交给文件
管理器时面板仍然可见"）。全量 4 层绿，darwin/universal 构建通过。

## 15:30-16:00 用户反馈"还是会出现遮罩"→ 结构性修复（透明底座）

用户报告先收再交的修复没生效。这次不再推理，做了**真机自动复现**：
临时脚手架（repro_tmp.go，env PAWCLIP_REPRO 驱动 show→reveal→再 show，
用完已删）+ go build 快速迭代（要 `-tags "sqlite_fts5 desktop production"` +
CGO_LDFLAGS="-framework UniformTypeIdentifiers -mmacosx-version-min=10.13"，
换进 bundle 后要重新 ad-hoc 签名）。

**取证结论（有日志实证的）：**
- 机器是双显示器（主屏 1440x900 + 左侧外接 1920x1080）。面板 recenter 跟
  鼠标走，同一会话里两次呼出可以落在不同屏——排查坐标问题必须先看 screens。
- `screencapture -l` 对面板、也对**其他任何 App** 的窗口都报
  "could not create image from window" → 本会话终端**没有屏幕录制权限**，
  macOS 对无权限进程的截图只合成壁纸。此前"区域截图=壁纸→面板透明"的
  推断全部作废。教训：用截图下结论前，先拿别的 App 窗口做权限对照。
- **抓到并修掉一个真崩溃**：对 Wails 的 WailsWebView（声明继承 WKWebView）
  调 `isDescendantOfView:` 运行时抛 unrecognized selector → SIGABRT。
  修法：不缓存引用、每次 subviews 浅遍历现找、respondsToSelector 前置、
  整段 @try（PawClip_WKWebView / PawClip_SyncBackdropFromDom）。

**修复（结构性）：** 内容层垫不透明圆角底座 g_cardLayer（圆角/裁剪从
WebView 层挪到底座层），颜色由 hide/show 时机 evaluateJavaScript 从 DOM
body 背景色同步（初值按系统外观猜），呼出时 invalidateShadow 防投影残影。
"内容未合成"的最坏结果从此是一块底色卡片，透明洞在构造上不存在。
panel/darwin.go 的 cgo LDFLAGS 补了 QuartzCore、WebKit 两个框架
（引用 [CALayer layer] 后 wails build 也需要）。
已记入 DESIGN.md §7 第 11 条（含取证教训）、新增第 12 条（WailsWebView 崩溃）。

**遗留风险（要向用户说明）：** 因为截图通道无权限，"底座在真屏上确实不透明"
没能由我亲眼验证；且 WebKit 为何在某些时刻不合成内容（用户真实触发点）仍未
定位——底座保证不透明，但内容恢复（重新合成）只有 evaluateJavaScript 这记
温和催促。若用户再遇到：请其描述遮罩形态/给一张系统截图，或给终端授屏幕录制
权限让我跑带探针的复现。探针已增强：diag 行加 screens/topleft/alpha。
